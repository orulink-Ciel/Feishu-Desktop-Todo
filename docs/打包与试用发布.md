# 飞书桌面待办：内部试用安装与发布

本版提供 Windows 和 macOS 安装包，适合先让少量同事试用任务读取、完成回写、窗口位置恢复和主题切换。安装包内置飞书 CLI 1.0.76，不需要安装 Node.js、Rust 或另外安装 CLI；每位同事仍需配置飞书应用，并用自己的飞书账户授权。

## 下载与安装

在 [GitHub Releases](https://github.com/orulink-Ciel/Feishu-Desktop-Todo/releases) 选择标有 Pre-release 的试用版，根据电脑下载：

| 电脑 | 文件 | 安装方式 |
| --- | --- | --- |
| Windows 10/11，64 位 Intel / AMD | `*-x86_64-pc-windows-msvc-setup.exe` | 运行安装程序，安装到当前用户目录 |
| Apple 芯片 Mac，macOS 13 或更新 | `*-aarch64-apple-darwin.dmg` | 打开 DMG，将应用拖到 Applications |
| Intel Mac，macOS 13 或更新 | `*-x86_64-apple-darwin.dmg` | 打开 DMG，将应用拖到 Applications |

本公司 Windows 同事请选择带 `internal-windows-x64` 的安装包，它预设公司值日表来源。其他三个安装包为通用版本。内部包不携带应用密钥或用户登录凭证；值日数据仍按飞书组织和表格权限读取。

Windows 安装程序在系统缺少 WebView2 时通过微软安装器补装，首次安装需要网络。Mac 使用系统 WebKit。

试用版 Windows 安装程序尚未做商业代码签名；Mac 使用临时签名，尚未做 Apple 公证。Mac 首次打开可能需按 [Apple 的打开方式](https://support.apple.com/zh-cn/102445)，在系统“隐私与安全性”中确认来源后打开。正式对外分发时改用 Developer ID 签名与公证，详见 [Tauri macOS 签名说明](https://v2.tauri.app/distribute/sign/macos/)。

## 首次连接飞书

管理员先准备可供试用人员使用的飞书应用，并启用 `task:task:read`、`task:task:write`；使用公司值日表时再启用 `base:record:read`。安装包不提供应用 ID、应用密钥和用户令牌。

在 Windows 打开应用安装目录的终端，运行内置 CLI 的配置向导：

```powershell
.\resources\lark-cli.exe config init --new
```

在 Mac 安装到 Applications 后，打开终端并运行：

```sh
"/Applications/飞书桌面待办.app/Contents/Resources/resources/lark-cli" config init --new
```

按向导配置管理员提供的应用资料，然后打开桌面待办，在连接飞书入口扫描授权二维码。应用始终使用当前用户自己的授权，查看和完成其负责的任务。配置、授权和任务缓存均保存在当前系统用户下。

通用下载包不含公司值日表链接、字段映射或人员名单，会显示“未配置公司值日来源”。带 `internal-windows-x64` 的公司 Windows 包已预设值日来源，需另外启用并授权 `base:record:read`。Mac 的公司值日功能由管理员填写本地构建配置后单独构建。飞书表格中的名单和顺序仍由管理员维护。

## 本地构建

先在当前系统安装 Node.js 22、Rust stable；Windows 另需 Visual Studio C++ Build Tools，Mac 另需 Xcode Command Line Tools。源码从 [项目仓库](https://github.com/orulink-Ciel/Feishu-Desktop-Todo) 获取。

```sh
npm ci
npm test
npm run package:public
```

Windows 输出位于 `src-tauri/target/release/bundle/nsis`，Mac 输出位于 `src-tauri/target/release/bundle/dmg`。在 Apple 芯片机器构建 Apple 芯片版本，在 Intel 机器构建 Intel 版本；不要把另一种架构的 CLI 直接塞进包里。

公司内部构建时，复制 `src-tauri/duty-config.example.rs` 为 `src-tauri/duty-config.local.rs`，填入文档和多维表格映射，再运行 `npm run package`。本地配置已加入 Git 忽略列表。`package:public` 即使发现本地配置，也始终采用示例配置。

## GitHub 构建与发布

`.github/workflows/desktop-build.yml` 在 `main`、`release/**` 分支或 `v*` 标签更新时构建三个平台。每个任务执行前端测试、Rust 测试、Clippy 和构建，检查打包的 CLI 版本；Windows 还在干净 runner 上静默安装并检查安装目录中的 CLI，Mac 检查应用签名和 DMG 完整性。

构建成果保存在 Actions 的 `desktop-<架构>` artifact 中，保留 14 天。三个任务全部成功后，将安装包、各平台 SHA-256 校验文件、运行检查记录和本文上传至 GitHub Pre-release。下载后可用校验文件核对安装包；不需要下载运行检查 JSON 才能使用。

这轮自动验证证明安装包能够构建、资源完整且内置 CLI 能启动；不同 Mac 上的首次安装提示、界面拖动和飞书扫码登录还需要同事进行实际试用。自动测试不读取真实账户、不修改飞书工作任务。
